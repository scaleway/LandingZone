# OPNsense Configuration Templates


This directory contains **reusable, sanitized** OPNsense configuration templates for common Scaleway hub-and-spoke deployments.

Templates are exported from a **working, tested** firewall (`fw-passive`) and cleaned of:
- root password hash (`CHANGE_ME` placeholder instead)
- autogenerated TLS certificate / private key (`<cert/>`)
- local admin source metadata / revision history

---

## `vpc-hub-spoke-fw.xml`: Hub firewall for a VPC hub-and-spoke

This is the **standard template** for an OPNsense firewall acting as the hub of a Scaleway Private Network hub-and-spoke topology.

### What it configures

| Component | Value in template | Notes |
|---|---|---|
| `lan` interface | `10.10.0.251/24` on `vtnet1` | Change to your hub LAN CIDR |
| `wan` interface | DHCP on `vtnet0` | Scaleway public NIC; `blockbogons` + `blockpriv` on |
| Gateway `HubVPC` | `169.254.169.254` on `vtnet1` (LAN) | Scaleway transparent router; monitor `10.10.0.1` |
| Static route `1111...` | `10.20.0.0/24` => `HubVPC` | Spoke-1 CIDR |
| Static route `2222...` | `10.30.0.0/24` => `HubVPC` | Spoke-2 CIDR |
| WAN rule `9f18...` | pass in any => any, `vtnet0` | Allows public SSH/HTTPS inbound |
| WAN rule `a4c6...` | pass out any => any, `vtnet0` | Allows outbound internet |
| LAN rule `f4bf...` | pass from **any** => any, `vtnet1` | Widened source so spoke subnets are allowed in |
| LAN=>Spoke-1 rule `7c6b...` | pass `10.10.0.0/24` => `10.20.0.0/24` | Explicit spoke-1 route in firewall rules |

### How to use for a **new deployment**

1. Copy the template to a node-specific file:
   - `cp templates/vpc-hub-spoke-fw.xml config/opnsense/fw-passive.xml`
   - `cp templates/vpc-hub-spoke-fw.xml config/opnsense/fw-active.xml`

2. **Adapt per firewall** (edit the copy, not the template):

   #### a. Hostname
   ```xml
   <hostname>FW-PASSIVE</hostname>   <!-- or FW-ACTIVE -->
   ```

   #### b. LAN IP (per node)
   ```xml
   <!-- fw-passive -->
   <ipaddr>10.10.0.251</ipaddr>
   <!-- fw-active -->
   <ipaddr>10.10.0.252</ipaddr>
   ```

   #### c. Spoke subnets (keep the same principle, change the CIDRs)
   Static routes (bottom of file):
   ```xml
   <staticroutes version="1.0.0">
     <!-- Spoke-1 -->
     <route uuid="11111111-1111-1111-1111-111111111111">
       <network>10.20.0.0/24</network>        <!-- CHANGE to spoke-1 CIDR -->
       <gateway>90b6e3f8-3a14-49b5-9ea1-60acc0e4aea6</gateway>
       <descr>Spoke-1 subnet via Hub VPC</descr>
       <disabled>0</disabled>
     </route>
     <!-- Spoke-2 -->
     <route uuid="22222222-2222-2222-2222-222222222222">
       <network>10.30.0.0/24</network>        <!-- CHANGE to spoke-2 CIDR -->
       <gateway>90b6e3f8-3a14-49b5-9ea1-60acc0e4aea6</gateway>
       <descr>Spoke-2 subnet via Hub VPC</descr>
       <disabled>0</disabled>
     </route>
   </staticroutes>
   ```

   Firewall rule for spoke-1 (in `<filter>`):
   ```xml
   <rule uuid="7c6b429e-1e3f-4355-95d0-e321a0240426">
     <type>pass</type>
     <interface>lan</interface>
     <ipprotocol>inet</ipprotocol>
     ...
     <source>
       <network>lan</network>
     </source>
     <destination>
       <address>10.20.0.0/24</address>      <!-- CHANGE to spoke-1 CIDR -->
     </destination>
   </rule>
   ```

   #### d. Root password
   ```xml
   <password>CHANGE_ME</password>
   ```
   OPNsense will require a GUI/console reset if the hash is not valid: or set the password after first boot.

   #### e. (Optional) Gateway monitor IP
   ```xml
   <monitor>10.10.0.1</monitor>   <!-- some always-on IP in your hub LAN; 10.10.0.1 is commonly the Scaleway hub gateway -->
   ```

3. **For fw-active (HA secondary)**, also:
   - change LAN IP to `10.10.0.252`
   - keep the same spoke routes (both nodes need them)
   - In a real CARP HA setup, also add the `<virtualip>` and `<hasync>` blocks from your HA reference config: this template is the *base routing/firewall state*.

4. Upload to a firewall (cloud-init `config` or manual SCP):
   ```bash
   scp -i <key> config/opnsense/fw-passive.xml root@<fw-passive-lan-ip>:/conf/config.xml
   ssh -i <key> root@<fw-passive-lan-ip> 'configctl filter reload && configctl routing configure'
   ```

### Validation after upload

```bash
# XML well-formed?
python3 -c "import xml.etree.ElementTree as ET; ET.parse('fw-passive.xml')"

# On the firewall
pfctl -sr | grep -E 'vtnet0|vtnet1'    # pass rules present
netstat -rn -4 | grep -E '10.20|10.30|169.254.169.254'   # routes active
```

## Template maintenance

When you improve the **live** fw-passive config (add aliases, WAN port rules, etc.), refresh the template:

```bash
# 1. download the live config
scp -i <key> root@<fw-passive-lan-ip>:/conf/config.xml tmp/fw-passive_config_downloaded.xml

# 2. rebuild the sanitized template
python3 tmp/build_fw_template.py
```

The generator script (`tmp/build_fw_template.py`) strips secrets and revision metadata automatically.
