## Repository layout

```
├── modules/                  # 26 reusable Terraform modules

│   ├── iam-group/ iam-policy/ iam-service-account/

│   ├── load-balancer/ dns/

│   └── bootstrap/            #   S3 state bucket + per-env config generation

│   ├── bootstrap/            #   run once per environment (day-0 seed: infra-ops
│   │                         #   + org setup)
│   ├── stages/
│   │   ├── 1-security/
│   │   ├── 2-networking/
│   │   ├── 3-security-appliances/
│   │   ├── 4-project-factory/

│   │   └── 6-interconnection/
│   └── envs/<env>/           #   per-env config, generated by bootstrap
├── samples/                  #   end-to-end examples (authentik-sso is the reference one)
├── scripts/
│   ├── apply.sh  destroy.sh  #   shared CLI (see scripts/lib/stages.sh)
│   ├── validate.sh           #   repo quality gate
│   ├── delete_s3.sh  delete_iam.sh  delete_vpn_secrets.sh   # destroy helpers
│   └── lib/stages.sh         #   single source of truth for stage orchestration
├── tests/                    #   offline regression suite (no cloud required)
├── Makefile                  #   bootstrap, apply/plan/destroy (STAGE= flag), init/validate/test
└── .terraform-version        #   pinned Terraform version (tfenv)
```

## Roles of the main pieces

| Piece | Role |
|---|---|
| `modules/` | 26 reusable, provider-close building blocks (VPC, IAM, compute, object storage, K8s, DNS, serverless, firewall, bootstrap...). Kept predictable and forkable. |
| `scw-lz/bootstrap/` | Day-0 seed, run once per environment: infra-ops project, state bucket, deploy identities, org setup, per-env config generation. |
| `scw-lz/stages/<N>-*/` | The six workload stages. Each declares its inputs and outputs and can run independently (see [architecture.md](architecture.md)). |
| `scw-lz/envs/<env>/` | Per-env configuration: `data/*-<env>.yaml` (resource definitions) + tfvars overrides. Bootstrap-generated files (`backend`/`providers`/`remote_state`/`5-backup`) live here too. |
| `scripts/` | Thin shared driver for apply/destroy/plan, repo quality gate, and destroy cleanup helpers. |
| `tests/` | Offline regression suite (**no cloud access, no credentials**); see [development.md](development.md). |

Each module and stage carries its own `README.md` with the specifics.
