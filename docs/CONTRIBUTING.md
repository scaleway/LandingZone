# Contributing

Thanks for taking the time to contribute to the Scaleway Landing Zone Toolkit.

This project is a Terraform toolchain: staged bootstrap + five workload stages, reusable modules, and a set of YAML-driven factories. The guidance below keeps PRs reviewable and the toolkit consistent. It is intentionally short - the detailed design notes live in [`docs/architecture.md`](architecture.md), [`docs/orchestration.md`](orchestration.md) and [`docs/operations.md`](operations.md).

## Report bugs / request features

Open an issue. Good reports include:

- what you expected, what happened instead, and the exact error
- the stage (`STAGE=3`) and environment (`ENV=dev`) you ran
- the version at `git log -1 --oneline`
- whether the failure reproduces with `make plan` (dry-run) vs `make apply`

## Development environment

Minimal local requirements (no cloud access needed for the local checks):

- make, POSIX shell (macOS or Linux)
- Terraform `1.16.5` (>= 1.14 works; `tfenv` picks up the pinned `.terraform-version`)

```bash
make init              # install providers/modules (offline-safe)
make test              # offline regression suite (no cloud, no credentials)
./scripts/validate.sh  # quality gate: fmt, terraform validate, lint, hygiene
```

For live verification against a deployment you also need the Scaleway CLI, an
owner key in `.creds/lz-creds.env`, and the per-env keys generated by
`make bootstrap` (see README "Prepare the owner key").

## Quick workflow

1. Branch from the latest base branch, with a `type/` prefix matching the
   change (`feat/`, `fix/`, `docs/`, `chore/`, `test/`), e.g.
   `feat/remote-bucket-encryption`.
2. Make your change. Keep it small and focused; one PR per logical change.
3. Run the local gates: `make test` and `./scripts/validate.sh`.
4. If the change touches stage 3 (firewalls), run the live battery on dev
   before opening the PR: `make fw-test-env ENV=dev`, then `make fw-test ENV=dev`
   - the battery must be all PASS (SKIPs are fine; FAILs are not).
5. Commit with a conventional-commit message (`feat:`, `fix:`, `docs:`,
   `chore:`, `test:`, `refactor:`; add a scope when useful, e.g.
   `fix(stage-3): ...`).
6. Always `make plan STAGE=n` (or `./scripts/apply.sh ENV=dev --plan --stage n`)
   before anything that applies resources. Never apply blindly.

## Repository conventions (enforced in review)

The toolkit has a few hard rules that keep it safe to operate by humans.
Please follow them - reviewers will push back otherwise.

### Single source of truth for topology and IPs

IPs, CIDRs, zones and instance settings live in the per-env factory YAML
(`envs/<env>/data/<topic>-<env>.yaml`). Code reads those values; it does not
re-declare them.

```terraform
# GOOD - value flows from the factory
hub_cidr = local.factory.hub_subnet_cidr   # rendered into opnsense-config.xml.tftpl
# BAD  - a second copy can drift from the YAML
# <content>10.10.0.0/24</content>
```

Only platform-fixed addresses (for example Scaleway's link-local metadata
gateway `169.254.169.254`, or loopback) may be literal.

### Never hardcode values that can change

Credentials, project IDs, bucket names, public IPs and management CIDRs must
never be hardcoded in code or committed files. Live per-env values live in
gitignored `-demo.*` files (or Secrets Manager); committed files are sanitized
templates with `CHANGE-ME` / documentation-range placeholders
(`198.51.100.10/32`, `ORG-ID`).

### Never open the management whitelist to 0.0.0.0/0

`management_cidrs = ["0.0.0.0/0"]` renders a `/0` reply route via the hub PGW
that collides with the system default route (egress PGW). The kernel default
gets pinned to the hub, and FW-own egress leaves via the hub public IP instead
of the egress masquerade. This rule is documented at the field itself - keep
it there. Pin a concrete operator `/32` or an office range. The IdP HTTPS
login in `samples/authentik-sso` is the one legitimate `0.0.0.0/0` (public
SAML endpoint); SSH is not.

### Per-environment keys, never the shared dir

Stages 3 and 5 and `test-firewalls.sh` resolve keys from
`scw-lz/keys-<env>/` (`keys-dev`, `keys-prod`). The legacy shared
`scw-lz/keys/` and un-ignored key dirs are forbidden - keys go in gitignored
`keys-<env>/` only, and every `keys-*` directory must stay covered by
`.gitignore`.

### Secret hygiene (non-negotiable)

Never commit, in any file:

- `.creds/` contents, `SCW_ACCESS_KEY` / `SCW_SECRET_KEY`, org IDs of live orgs
- `keys-<env>/` private keys (only `.pub` files ship, as specified overrides)
- `*-demo.yaml` / `*-demo.tfvars` (live values; already gitignored)
- `test-firewalls.env` (live IPs/UUIDs)

When in doubt, `git status --short` must show no `keys-*`, `.creds/`,
`*-demo.*` or `*.tfvars` with real values before you open the PR.

## Testing and staging guidance

- `make test` (offline) and `./scripts/validate.sh` run without credentials -
  always green before a PR.
- Any stage change: `make plan STAGE=n` first. Live apply only with explicit
  review.
- Stage 3 firewall changes: also run `make fw-test-env ENV=dev` +
  `make fw-test ENV=dev` against the dev deployment. Never change the
  firewall template (`opnsense-config.xml.tftpl`) without re-running the
  battery.
- `make clean` removes `.terraform/` caches and `.terraform.lock.hcl`; lock
  files are gitignored, so they are never part of a PR.
