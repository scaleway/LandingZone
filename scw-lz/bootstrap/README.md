# Stage: Bootstrap (day-0 seed: org setup + infra foundation)

The **single day-0 stage**. It owns the `infra-ops` project and the org-layout:
one stage = one key = one project. Everything else lives in the `lz-<env>`
project under the `lz-<env>` deploy key (stages 1-6).

## What It Creates

| Resource | Purpose |
|----------|---------|
| `infra-ops` project | Dedicated project for state + operations |
| `lz-ENV-terraform-state` bucket | S3-compatible Object Storage for Terraform remote state (locked, versioned). `state_bucket_prefix` is REQUIRED: the shared user prefix for all bootstrap-named buckets (state, audit, image-import, backup/DR); a frozen creation timestamp is appended automatically so names become `<prefix>-<env>-<purpose>-<timestamp>` (e.g. `lz-myorg-dev-backup-20261113t091500z`, lowercased so S3 accepts it) - globally unique even for identical prefixes |
| Bootstrap IAM application + API key | CI/CD deployment identity (default project = `infra-ops`) |
| lz deploy IAM application + API key | stages 1-6 identity (default project = `lz-<env>`) |
| Both SAs' IAM policies | org-wide deploy + IAM management, project-scoped state/secret access |
| `lz-<env>` project | the tenant project all stages 1-6 deploy into (from the org YAML factory) |
| Org IAM groups, service accounts, SSH keys, KMS, audit bucket, secrets, SSO | org-level resources, driven by `envs/<env>/data/org-<env>.yaml` |
| Secret Manager secret | stores bootstrap credentials for CI/CD pipelines |
| `envs/ENV/backend-ENV.tfvars` | auto-generated per-env S3 backend config for downstream stages |
| `envs/ENV/providers-ENV.tfvars` | auto-generated per-env shared provider config |
| `envs/ENV/remote_state-ENV.tfvars` | S3 remote-state vars **plus `stage0_state_path`** (path to THIS stage's local state, read by stages 1-6 for `project_ids` / SSH keys / environment) |
| `envs/ENV/5-backup-ENV.tfvars` | backup stack config for stage 5 (buckets/KMS live in the `lz-<env>` project and are CREATED by stage 5) |
| `.creds/lz-ENV-infra-ops.env` | bootstrap SA key (gitignored) |
| `.creds/lz-ENV.env` | lz deploy key (gitignored) |

It uses **local state** (`envs/<env>/bootstrap-<env>.tfstate`): it is the seed.

Every environment has its own config folder under `scw-lz/envs/<env>/`:

```
scw-lz/envs/<env>/
  bootstrap-<env>.tfstate         # LOCAL state of this stage
  backend-<env>.tfvars            # generated by bootstrap (this stage)
  providers-<env>.tfvars          # generated by bootstrap (this stage)
  remote_state-<env>.tfvars       # generated by bootstrap (this stage)
  5-backup-<env>.tfvars           # generated by bootstrap (this stage)
  0-org-setup-<env>.tfvars        # optional var overrides for the org factory
  data/                           # per-env YAML factories (org/security/
                                  # networking/security-appliances/projects)
```

To bootstrap an environment, run `make bootstrap ENV=<env>` (or this stage
directly with `-var="environment=<env>"`). Stages then read this stage's
outputs via a LOCAL `terraform_remote_state` (path = `stage0_state_path` from
`remote_state-<env>.tfvars`) and each other's state via S3.

## Remote State Layout (per-stage paths)

```
lz-ENV-terraform-state/           # S3 (owned by bootstrap)
  stage-1/terraform.tfstate       # security
  stage-2/terraform.tfstate       # networking
  stage-3/terraform.tfstate       # security appliances
  stage-4/terraform.tfstate       # project factory
  ...other stages...              # 5-backup / 6-interconnection
bootstrap state                   # LOCAL: envs/<env>/bootstrap-<env>.tfstate
```

## Usage

Prefer the Makefile driver (`make bootstrap ENV=...`) - it wires the org
factory var-file, credentials and local state for you. Manual equivalent:

```bash
# 1. Set Scaleway credentials (SCW_ACCESS_KEY / SCW_SECRET_KEY / ORG_ID)
#    Day-0 uses YOUR owner key; after the first run the generated
#    .creds/lz-<env>-infra-ops.env is loaded automatically.

# 2. Plan & Apply (uses LOCAL state) - repeat once per environment
cd scw-lz/bootstrap
terraform init
terraform plan \
  -var="organization_id=<org-id>" \
  -var="environment=dev" \
  -var="region=fr-par" \
  -var="zone=fr-par-2" \
  -var="enable_state_lock=true" -var="state_retention_days=365" -var="enable_state_sse=true"
terraform apply -auto-approve -state=../envs/dev/bootstrap-dev.tfstate
```

## After Bootstrap

Everything is generated: both creds files, backend/providers/remote_state/
5-backup tfvars, and both identities. `make apply STAGE=<n>` (or `make apply`)
just work; each stage auto-loads its project-scoped key.

## Components

- **`modules/bootstrap/`**: reusable module: infra-ops project, state bucket,
  bootstrap SA + IAM (no backup buckets - those moved to stage 5).
- **`templates/`**: templates for `backend-<env>.tfvars`,
  `providers-<env>.tfvars`, `remote_state-<env>.tfvars` (incl.
  `stage0_state_path`) and `5-backup-<env>.tfvars`.
